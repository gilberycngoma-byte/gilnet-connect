## Current runtime setup

- Copy `.env.example` to `.env` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Local Vite development maps these public values to server auth automatically. The Electron build embeds only these public values.
- Packaged Electron serves the bundled `dist/client` and `dist/server` from a loopback-only local server. It never loads the hosted web app. Each Windows account enters its Supabase service-role/secret key in **File > Configure Supabase server key**; Electron encrypts it with `safeStorage` and never includes it in the installer.
- Apply `supabase/migrations/20261117064500_staff_pin_setup_required.sql` and `supabase/migrations/20261117072000_staff_pin_auth_functions.sql` to retain compatibility with existing staff database rows. The current app uses password-only staff sign-in; it does not offer PIN setup or PIN login.
- Web, Android, and Electron staff management use the authenticated `gpm-mobile-api` Supabase Edge Function. Android and Electron attendance, staff-recipient lookup, and private-message retrieval use the same function. Apply `supabase/migrations/20261116050000_staff_attendance.sql` before using staff attendance. Keep `SUPABASE_SERVICE_ROLE_KEY` in the Edge Function environment only; never set it with a `VITE_` prefix or package it in an app. Other trusted server-side operations may still need a service-role key in their server environment.
- Apply `supabase/migrations/20261116060000_property_backups_storage.sql` to provision the **private** `gilnet-backups` Storage bucket. It limits read, list, upload, and overwrite access to authenticated Admin, Manager, or Supervisor accounts within their own property folder.
- Apply `supabase/migrations/20261118050000_property_backup_scheduler.sql` and deploy `gpm-property-backup-worker` to enable server-side property schedules. Before the migration, set a strong `GPM_BACKUP_CRON_SECRET` Edge Function secret and store the same value in Supabase Vault as `gpm_backup_cron_secret`; neither value belongs in app code or `.env` files. The migration schedules the worker through `pg_cron`/`pg_net`. Deploy the updated Admin Hub read/manage functions to the same GPM Supabase project for Super Admin status and recovery links. Property Admins choose hourly, daily, weekly, monthly, or “Never” (queue a snapshot after each saved entry, processed within about a minute). Automatic rotation retains at most 30 snapshots and removes files older than 30 days. Server snapshots include only cloud-synced records and exclude private chats; unsynced device data is not included.
- Private chats are fetched through an authenticated server function on web and the authenticated `gpm-mobile-api` Edge Function in Android and Electron. Both paths return messages only to their sender and intended receiver. Configure matching Supabase row-level and realtime policies on `operation_rows`; private rows must not be readable by other property staff.
- Electron creates `Documents/GILNET GPM CONNECT/{propertyCode}` with `files`, `backups`, and `database` subfolders. Property codes may contain letters, numbers, spaces, hyphens, and underscores (up to 32 characters); path separators are rejected. The current app continues to use its existing local IndexedDB-backed store; the Documents folder keeps local JSON snapshots rather than replacing that store.
- To run the latest workspace code in Electron locally, start `npm.cmd run dev` in one PowerShell terminal, then `npm.cmd run desktop:open` in another. The unpackaged Electron app loads `http://localhost:5173`; Supabase features still require the configured backend.
- Use `npm run electron:build` for the Windows installer and `npm run cap:sync` / `npm run cap:open:android` for Android.
- New property setup captures one property billing/contact email, separate from individual user and staff login emails. Subscription checkout is not connected yet, so no account is charged.
- Admin Hub-managed subscription end dates use `supabase/migrations/20261116070000_subscription_expiry.sql`. Deploy the updated `gpm-announcements` Edge Function to enable a property-targeted in-app reminder for the property Admin during the final seven calendar days in Africa/Lusaka. The app checks at sign-in and every six hours while open; reminders are only generated for active subscriptions with an end date. No migration or function deployment is performed by the local app build.
- GILNET Connect ticker promos can be targeted to one property or all properties from the Admin Hub. Apply `supabase/migrations/20261118020000_gpm_announcement_property_target.sql` and deploy the updated `gpm-announcements` Edge Function; existing announcements without a property target remain global.
- The login About page and User Agreement are managed from the Admin Hub. Apply `supabase/migrations/20261118040000_gpm_app_content.sql` before deploying the updated Admin Hub Edge Functions and GPM app. A changed User Agreement text or effective date increments its revision and requires renewed acceptance; public content is read-only to app users.

## Electron offline use and Google Drive backup

The Windows Electron installer includes the production client and server bundles and serves them locally. Public Supabase configuration is embedded at build time; an optional service-role key can be entered on each Windows account and is encrypted with Electron `safeStorage`, never bundled. Staff administration, attendance, and private-message retrieval use the deployed `gpm-mobile-api` Edge Function and do not require that local key. Other desktop-only server operations that need it will direct users to **File > Configure Supabase server key**. Normal data synchronization uses the signed-in user's public key and RLS policies. Offline edits remain in local storage/IndexedDB and queue for Supabase when connectivity returns. The client can open offline, while cloud sign-in, team synchronization and backups require internet access and correctly configured Supabase tables, policies, realtime publication and the private `gilnet-backups` bucket.

Staff administration and private-message retrieval in Electron use the same deployed Edge Function as Android. Deploy it to the existing Supabase project (`qyawsbiipskhpstnemno`) with:

```sh
npx supabase login
npx supabase link --project-ref qyawsbiipskhpstnemno
npx supabase functions deploy gpm-mobile-api
```

The function URL is `https://qyawsbiipskhpstnemno.supabase.co/functions/v1/gpm-mobile-api`. Its `verify_jwt` gateway check is disabled so browser preflight requests can reach it; the function itself validates every access token with Supabase Auth before authorizing a property role. Ensure the project has the service-role key available as a server-side Edge Function secret. Do not copy it into `.env`, the APK, or the Electron renderer. Until this function is deployed, those mobile/desktop features will return a server error.

Google Drive is an optional private backup/restore for the signed-in property's local operational data. It uses Google's `drive.appdata` scope and stores OAuth refresh tokens with Electron `safeStorage`; it does not back up login sessions, credentials, or staff-user caches. Backups can include guest details, messages and sales. Restoring merges records and retains existing local entries; Supabase remains the authority for team data and permissions.

Create a Google OAuth 2.0 **Desktop app** client and enter its public Client ID in Account > Google Drive backup. The value is saved on that device; a frontend build can prefill it with `VITE_GOOGLE_OAUTH_CLIENT_ID`. In packaged Electron, enter the ID once in the bundled app; it remains saved on that device. Do not configure a client secret or service-account key in the app. Build the Windows installer with:

```sh
npm run package:windows
```

## Android

The Android app is a local Capacitor bundle. Its web assets, login screen, and GILNET splash screen are packaged in the app; no hosted website URL is configured. Build and copy the app with:

```sh
npm run build
npx cap sync android
npx cap copy android
```

The bundled login screen opens offline, but Supabase authentication, password/PIN verification, and cloud synchronization require internet access. Android sync retries when the native network reconnects and when the app returns to the foreground. Non-overlapping offline field changes merge automatically; conflicting edits to the same field stay queued for review to avoid losing either version. Set `VITE_SUPABASE_URL` to `https://qyawsbiipskhpstnemno.supabase.co` and provide the project's public `VITE_SUPABASE_PUBLISHABLE_KEY` in the local `.env` before building. Never bundle a service-role key.

## First-time user guide

The in-app First-time Guide is available from the login screen and the operations menu on desktop and mobile. It covers sign-in, role-based workspaces, bookings, rooms, tasks, messages, offline sync, privacy, and payments. Pending changes retry quietly while the app is open and when connectivity returns. A new message must sync under its original sender's account; if another account is signed in, the queued message stays local and retries later rather than being sent as the wrong person.

Build a fresh debug APK with `npm run android:build:debug`. Build a signed release APK with `npm run android:build` and the existing `ANDROID_KEYSTORE_PATH`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD` environment variables. The build command regenerates and syncs the web bundle before packaging it. Keep the same signing key for app updates.

The packaged Android build targets Chromium 80-compatible JavaScript and removes CSS cascade-layer syntax for older vendor WebViews. The Android minimum is API 24 (Android 7.0). Huawei compatibility depends on firmware support for Android APKs; HarmonyOS NEXT is not covered by HarmonyOS 3's Android-app compatibility layer. Test on the specific device before distribution.

Staff management, attendance, staff-recipient lookup, and private-message retrieval call the same `gpm-mobile-api` Edge Function used by Electron. Apply `supabase/migrations/20261116050000_staff_attendance.sql` to the Supabase project to create the attendance tables and check-in/out functions. The app uses the configured Supabase URL and public key; the service-role key remains server-side.

Android requests internet access and microphone access when voice recording is used. Image/file attachments use Android's system picker and do not require broad phone-storage access; the app does not request `READ_EXTERNAL_STORAGE`, `READ_MEDIA_IMAGES`, or `MANAGE_EXTERNAL_STORAGE`.

## Sign-in, password setup, and email delivery

- The Management login offers GitHub and Google OAuth on web/PWA, Electron, and Android. The Supabase project being connected to a GitHub repository does not enable GitHub sign-in: create a GitHub OAuth App and a Google Web OAuth client, then enable both providers in Supabase **Authentication > Sign In / Providers**. For each provider, use `https://qyawsbiipskhpstnemno.supabase.co/auth/v1/callback` as its provider callback URI and store the provider client ID/secret only in Supabase.
- In Supabase **Authentication > URL Configuration**, set the real web app URL as the Site URL and allow the deployed web app's `/login` callback, local development callbacks (`http://localhost:5173/login` and `http://127.0.0.1:5173/login`), and the native callback `gilnet://auth/callback`. Electron and Android return through that custom scheme. Do not add OAuth client secrets to `.env`, the APK, or the Electron renderer.
- Provider sign-in does not create or promote GILNET administrators. It is accepted only when the authenticated Supabase user already has the `Admin` role in `user_roles` for the entered property code. Link each provider identity to the existing Admin Supabase account first; a different or unassigned account is rejected. Google/GitHub may offer a provider-managed passkey or device biometric when configured on that account and supported by the device. GILNET does not collect fingerprints or store app passkeys.
- Staff sign in with their email address and password. Authorized property managers and administrators create each staff account with one email used for both contact and sign-in. Supabase sends the property code and a generated login password to that address. Staff may keep the password or change it in Account > Edit Profile > Change Password. Password reset requests continue to use a single-use link that expires after 10 minutes.
- Admins, Managers, and Supervisors sign in with email and password. Newly provisioned management accounts receive a six-digit email confirmation code. Users can request a recovery email to reset their own password; Admins can also initiate a reset for another management account, and property managers can send staff a password-reset email.
- Password sign-in locks an account for 15 minutes after three incorrect attempts within a 15-minute window. Apply `supabase/migrations/20261116080000_login_lockout.sql` and deploy the `password-login` Edge Function. The login screen shows recovery guidance and a direct GILNET Support email link.
- Configure email delivery with a verified sender address and custom SMTP provider. Set the sender display name to **GILNET GPM** and use a sender address on a domain you control. The linked project config sets email OTPs to six digits with `auth.email.otp_expiry = 600` (10 minutes); management email confirmation still uses a six-digit code. Password recovery uses only a secure link, and the recovery template at `supabase/templates/recovery.html` includes the property code and link. Supabase consumes the link when verified; it cannot be reused.
- The legacy `pin_hash` and `pin_setup_required` database columns and PIN functions remain only for compatibility with existing production data; the current app uses password-only staff authentication. Existing PIN-only staff can use **Forgot password?** and their registered login email to set a password.
- Keep the Supabase service-role key only in trusted server environments or Edge Function secrets; it is required by the server for staff account creation and credential resets, and must never be bundled in the app.
